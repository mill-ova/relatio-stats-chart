# Стани і скраб

## Стан збирається з двох компонентів

Власної осі `State` в обгортці немає. Loading і Empty приходять окремо на
`Stats Header` і на `Chart Plot`.

Чому так: слот не вміє слухатися осі обгортки, а в продукті верх і серія точок
тягнуться різними запитами — верх часто готовий раніше за графік. Тому вісь
живе в кожному компоненті, а обгортка лишається чистим контейнером.

| Комбінація | Коли |
|---|---|
| Header Default + Plot Default | дані є |
| Header Loading + Plot Loading | перший запит або зміна періоду |
| Header Default + Plot Loading | метрика вже прийшла, точки ще ні |
| Header Empty + Plot Empty | у користувача ще немає жодної вправи |

**Range Switch і Period Nav справжні в усіх станах.** Не блокувати: користувач
має право перемикнути період, поки дані їдуть.

## Loading

Кістки `_Skeleton Bone` замінюють цифри й полотно:

```
Header    120 × 40 (hero) · 88 × 12 (лейбл) · 408 × 14 і 220 × 14 (інсайт)
Plot      360 × 150 полотно · 4 × (28 × 10) Y-підписи · n × (34 × 10) X-підписи
```

База кістки — `bg/brand-disabled` на `opacity/40`, шимер на повну. Прозорість
саме на базі: якщо поставити її на корінь, згасне й шимер.

Тексту немає — стан треба **озвучити для скрінрідера** (`aria-busy` / RN
`accessibilityState={{ busy: true }}`), бо кістки самі нічого не кажуть.

Автоматика в прототипі: Loading проганяється ~700 мс на кожному перемиканні
періоду. У проді — доки їде запит.

## Empty

| Елемент | Що показує |
|---|---|
| Hero | «—» на `text/tertiary`, не «0 %» |
| Друга метрика | **вимкнена** |
| Інсайт | «One exercise is enough to start this chart. After that, it updates daily.» |
| Полотно | приглушена демо-крива на `border/strong`, без area й без глоу |
| Підпис на полотні | «Your line starts here» по центру, `text/tertiary` |
| Скраб | вимкнений |

Гридлайни й підписи осей лишаються: вони показують, що тут буде шкала.

Дві ролі розведені: **інсайт запрошує**, підпис на полотні лише **позначає
місце**. Раніше та сама інструкція стояла двічі.

Друга метрика вимкнена свідомо: «0» на видному місці демотивує сильніше, ніж
його відсутність.

## Скраб

**Жест:** затиснути на полотні → позначка стає на найближчу точку; вести пальцем
→ позначка переїжджає; відпустити → зникає.

**Що показує:** піл над точкою, «день · значення» (`Thu · 6.0%`).

**Hero-цифра НЕ змінюється.** Спершу було навпаки — значення переїжджало в
шапку, як в Opal. Не працює: палець унизу екрана, а зміна вгорі — її ніхто не
бачить. Hero — про період, точка — про день; це різні рівні, і їм не варто
жити в одному місці.

**Snap до точки, не вільне ковзання.** Значення існують тільки в точках; проміжні
позиції були б вигадкою.

**Регістр підпису — sentence case, як підписи осі X** (`Thu`, `14 Jul`,
`Jan 26`). Капсом у блоці говорить тільки лейбл метрики (`IN CONTROL`), і піл із
ним не конкурує.

**Де вимкнено:** Loading (нема чого показувати) і Empty (крива демонстраційна —
скраб по ній показував би неправду).

**Доступність:** жест недоступний зі скрінрідером, тому точні значення мусять
бути доступні й іншим шляхом. Мінімум — озвучувати сумарну метрику й період;
краще — окремий текстовий розріз по днях.
