# Relatio — Stats Chart

Блок статистики на екрані Progress: одна метрика, речення-інсайт, перемикач
періоду і лінійний графік зі скрабом. Тут усе, що потрібно для імплементації —
живий прототип, компоненти React Native і докси.

| | |
|---|---|
| **Figma (сторінка)** | `↪ Charts` — секції Stats Chart · Stats Header · Chart Plot |
| **Stats Chart** | `18360:92367` — обгортка на двох слотах |
| **Stats Header** | `18360:92366` — верх, вісь State |
| **Chart Plot** | `18360:88565` — полотно, Range × State + Show pointer |
| **_Pill** | `18442:93992` — піл значення під пальцем |
| **Референс мови** | Opal — чорний простір, один світний герой, градієнт лише на мілстоуни |
| **Розмір макета** | 440 × 956 (iPhone 17 Pro Max), блок 408 у ширину |

## Структура

```
prototype/index.html          живий прототип: перемикання періодів, скраб,
                              Loading / Empty, Dark / Light, дебаг-панель
react-native/                 компоненти + токени + геометрія
docs/anatomy.md               анатомія та API чотирьох компонентів
docs/tokens.md                усі використані токени зі значеннями
docs/data-and-geometry.md     дані кривих, формула сплайна, координати полотна
docs/states-and-scrub.md      Loading / Empty і поведінка скраба
docs/copy.md                  правила копірайту
docs/changelog.md             Було / Стало відносно старого екрана
```

**Почніть з `prototype/index.html`** — відкрийте у браузері, поперемикайте
періоди, затисніть на графіку. Це джерело істини: числа в RN-компонентах
збігаються з ним і з макетом.

## Логіка блоку

Порядок читання: **значення → сенс → масштаб → доказ.**

1. **Hero-цифра** — «+8%» із градієнтом і капс-лейблом `IN CONTROL`. Одна метрика
   на блок.
2. **Речення-інсайт** — одне число, і саме те, якого немає на екрані (кількість
   вправ). Каже, що цифра значить і що робити далі.
3. **Range Switch** — Week / Month / All time. Задає масштаб і кількість точок.
4. **Period Nav** — крок усередині вибраного масштабу. В All time ховається.
5. **Полотно** — сплайн із глоу, area-фейд, чотири гридлайни. Крапок немає.
6. **Скраб** — затиснув, і над найближчою точкою зʼявився піл «день · значення».

## Правила, які не варто «оптимізувати»

- **Стан не один на весь блок.** Loading і Empty приходять окремо на верх і на
  полотно: у продукті метрика й точки тягнуться різними запитами.
- **Range Switch і Period Nav активні в Loading.** Користувач має право
  перемикнути період, поки дані їдуть.
- **Hero не змінюється під час скраба.** Значення точки показує піл. Пробували
  навпаки — палець унизу, зміна вгорі, її ніхто не бачить.
- **Глоу — це світло, не тінь.** Дубль лінії з блюром під нею. Власних тіней у
  блоці немає за домовленістю DS.
- **Area не тримає прозорість руками.** Градієнт із двох токенів, другий стоп =
  фон екрана. На іншому фоні під кривою зʼявиться плашка — це відомий трейд.
- **Крива — конкретна формула.** Catmull-Rom із плечима 1/6 на кінцях і 1/3 у
  середині. Інша інтерполяція = інша крива, макет розійдеться з кодом.
- **Одиниці — у лейблі, не у значенні.** `ACTIVE DAYS` / `12`.
- **Прозорість — на окремому шарі.** Інакше гасить текст (піл) або шимер (кістка).

## Що ще не зроблено

- Дані підставляються моками. Контракт на дата-шар не описаний — це наступний крок.
- Скраб на PanResponder. Якщо на 30 точках буде помітний лаг — переносити на
  gesture-handler + Reanimated (UI-потік).
- Сегменти й стрілки в RN — заглушки на токенах; у проді підставити `Button` і
  `Icon Button` із DS.
- Скраб недоступний зі скрінрідером — потрібен текстовий шлях до значень.
