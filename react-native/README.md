# React Native — Stats Chart

Чотири компоненти, які збирають блок статистики, плюс токени й геометрія.
Код відповідає макету 1:1: криві генеруються тією ж формулою, що дала
`vectorPaths` у Figma, тому міряти по пікселях не треба.

```
tokens.ts          резолвнуті значення токенів + типографіка (у проді читати з теми DS)
chartGeometry.ts   полотно, дані періодів, spline(), пошук найближчої точки
StatsChart.tsx     обгортка: Header → Range Switch → Period Nav → Chart
StatsHeader.tsx    hero-метрика (градієнт), друга метрика, речення-інсайт
ChartPlot.tsx      SVG-полотно: area, глоу, лінія, гридлайни, поінтер, стани
Pill.tsx           піл значення під пальцем
SkeletonBone.tsx   кістка скелетона з шимером
```

## Залежності

| Пакет | Для чого | Обовʼязково |
|---|---|---|
| `react-native-svg` | усе полотно, hero-градієнт, іконки | так |
| `react-native-reanimated` (3) | шимер скелетона | так |
| `expo-blur` / `@react-native-community/blur` | скло під пілом | ні — піл читабельний і без нього |
| `react-native-gesture-handler` | якщо скраб треба на UI-потоці | ні — базово PanResponder |

## Мінімальний виклик

```tsx
const [range, setRange] = useState<RangeKey>('week');

<StatsChart
  range={range}
  onRangeChange={setRange}
  periodLabel="Last 7 days"
  heroValue="+8%"
  insight={{
    text: 'Up from last week — 10 exercises did that. Keep the rhythm.',
    accent: '10 exercises',
  }}
  theme={scheme === 'dark' ? 'dark' : 'light'}
/>
```

Дані підставляються через `values` (масив відсотків) — довжина задає кількість
точок. Без `values` компонент бере демо-дані з макета.

## Що треба замінити на продові компоненти

Сегменти й стрілки крокера тут — заглушки на токенах, щоб пакет запускався
ізольовано. У проді:

- сегменти → **Button / Small**, вибраний `Type=Primary`, решта `Type=Secondary`
- стрілки → **Icon Button / Ghost**, мод `Sizing = Small` (40)

Окремого сегмент-контрола в DS немає і не планується — це кнопки.

## Місця, де легко зробити не так

1. **Крива.** `spline()` має плечі 1/6 на кінцях і 1/3 у середині. Будь-яка інша
   інтерполяція (monotone, cardinal із іншим tension) дасть іншу форму — макет
   і код розійдуться.
2. **Area не має альфи.** Це градієнт із двох токенів, другий стоп = фон екрана.
   Не замінювати на `bgBrandSubtle` з прозорістю: на іншому фоні зʼявиться
   сірий прямокутник.
3. **Глоу — не тінь.** Це дубль лінії з блюром під нею. `shadowColor` не давати:
   у компоненті власних тіней немає за домовленістю DS.
   Якщо `FeGaussianBlur` на Android гальмує — замінити на 2–3 стеки строуків
   (6 px / 0.10, 4 px / 0.16, 3 px / 0.24) замість фільтра.
4. **Hero не рухається під час скраба.** Значення точки показує піл. Спершу
   було навпаки — цифра змінювалась у шапці, і цього ніхто не бачив: палець
   унизу екрана, зміна вгорі.
5. **Скелетон: opacity живе на базі, не на root.** Якщо поставити прозорість на
   корінь кістки, згасне і шимер, і кістка перетвориться на пляму.
6. **Range Switch і Period Nav активні в Loading.** Не блокувати їх, поки їдуть
   дані — користувач має право перемикнути період одразу.

## Доступність

- `ChartPlot` у Loading віддає `accessibilityState={{ busy: true }}` — кістки
  самі нічого не кажуть.
- Підпис періоду має `accessibilityLiveRegion="polite"`, щоб зміна періоду
  озвучувалась.
- `reduceMotion` вимикає шимер. Прокидати з `AccessibilityInfo.isReduceMotionEnabled()`.
- Скраб — не єдиний шлях до значень: точні числа мають бути доступні й текстом
  (наприклад, у детальному екрані), бо жест недоступний зі скрінрідером.
